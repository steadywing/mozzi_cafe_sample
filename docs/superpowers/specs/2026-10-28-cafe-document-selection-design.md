# 05 카페정보문의 문서 분류 변경 설계

사용자가 승인한 흐름은 질문 → Jev의 문서별 관련 여부 분류 → Python의 실제 파일 읽기 → 원문 기반 답변이다.

## 접근과 범위

기존 동의어 매칭은 표현을 계속 관리해야 한다. 벡터 검색은 정해진 7개 문서에 추가 구성 요소가 필요하다. 사용자는 문서 목록을 보고 Jev가 관련 문서를 분류하는 방식을 선택했다.

- 고정된 7개 문서에 ID·파일명·제목·설명을 명시한다. 모델에는 ID·제목·설명만 전달한다.
- Jev에 명확성 Choice와 문서별 relevant/irrelevant Choice를 한 요청으로 전달한다. 선택 결과는 고정 Literal 문서 ID 목록으로 보관한다. query는 현재 입력을 보존하며 후속 문맥도 전달한다.
- Python은 선택된 ID에 연결된 파일만 읽는다. 여러 문서를 선택할 수 있으며 중복은 제거한다. 전체 Markdown과 실제 출처를 유지한다.
- 모호한 질문은 확인 질문, 관련 문서가 없거나 원문에 답이 없으면 확인 불가로 안내한다.
- 답변은 조회한 원문만 근거로 사용하고 기존 출처 제한을 유지한다.
- 노트북·관련 테스트·분류 프롬프트를 수정한다. API·화면·원본 데이터·의존성·git 상태는 변경하지 않는다.

## 검증

대체 클라이언트로 카탈로그 전달, 선택 문서 읽기, 다중 선택, 중복, 미등록 ID, 빈 선택, 후속 대화와 출처 보호를 검증한다. 전체 unittest와 노트북 문법도 확인한다. 실제 모델 검증 여부는 별도로 보고한다.
