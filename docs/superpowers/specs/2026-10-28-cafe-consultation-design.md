# 05 카페정보문의 노트북 설계

사용자 요청은 03 상품추천 다음으로 카페정보문의 흐름을 실습할 주피터 노트북을 만드는 것이다.

## 접근

기존 `consultation_query.md`로 질문을 구조화하고 일반 Python 함수로 로컬 문서를 조회한 뒤 `consultation_response.md`로 근거 답변을 만든다. 7개 문서가 전체 약 7KB이므로 명시적 주제·동의어 조회가 충분하다. 임베딩·벡터 DB는 설치와 외부 호출을 늘려 이번 작은 실습에는 도입하지 않는다.

## 흐름

1. 필요한 최소 `CustomerInput`, `HistoryMessage`, `ConsultationQuery`, `ConsultationDocument`, `ConsultationState`, `SessionState`를 노트북에 직접 정의한다.
2. 카페 문서와 기존 Markdown 프롬프트를 읽고 데이터 형식을 확인한다.
3. 모델이 현재 질문과 history로 query/topic/needs_clarification/question을 정리한다. 질문이 명확한데 자료가 없는 경우에는 모호한 질문으로 취급하지 않는다.
4. `search_cafe_information(query, topic)`는 명시적 주제·동의어로 실제 파일을 선택해 source/title/content를 반환한다. 임의 경로를 모델에서 받아 읽지 않는다. 여러 주제의 문서를 함께 반환할 수 있고 관련 문서가 없으면 빈 목록이다.
5. 모델은 검색 결과에 있는 사실만으로 짧게 답한다. 출처는 조회한 문서만 허용한다. 실제 조회한 source 목록을 답변 JSON Schema의 enum으로 제한하고 사후에도 범위를 확인한다. 근거가 없으면 확인할 수 없다고 안내한다. 영업시간과 시설을 일반 상식으로 보충하지 않으며 가상 주소라는 원문 조건을 유지한다.
6. 처리 함수는 상태를 복사하고 query, topic, documents, answer를 남긴다. 후속 질문에는 직전 문맥을 사용한다. 모호한 질문이면 필요한 확인 질문 하나만 반환한다.

## 실습과 범위

- 함수 작성 → 직접 호출 → 결과 확인 → 전체 흐름 연결을 유지한다.
- 영업시간·마지막 주문, 위치·주차, 반려동물·콘센트, 유아용 의자·예약 등 자료 없음, 모호한 질문과 후속 답변을 확인한다.
- `notebooks/05_카페정보문의.ipynb`와 관련 테스트만 추가한다. 기존 프롬프트 보완이 꼭 필요하면 추가 전 이유를 확인한다. 기존 API·화면·공통 State와 원본 자료는 바꾸지 않는다.
- 기존 OpenAI Responses와 Pydantic, 표준 라이브러리만 사용한다. notebooks 작업 위치를 안내하고 루트 탐색·경로 보정·assert·%run은 넣지 않는다.
- 원본 고객·주문 자료는 이 흐름에 필요하지 않으므로 읽거나 모델에 전달하지 않는다.

## 검증

실제 문서 조회 결과와 출처 제한, 다중 주제, 미조회와 모호함 구분, 원본 상태 보존·후속 대화 연결을 unittest에서 확인한다. 노트북 문법·주석·출력 비움과 전체 회귀를 검증한다. 실제 모델 호출은 대체 응답 테스트와 별도로 확인하고 보고한다.
