# 구매 통계를 담는 고객 프로필

## 사용자 요청과 결정

CustomerProfile에 고객 적립금·스탬프를 추가하고 preferences에는 구매 내역 통계를 담는다. 고객 직접 선호와 구매 관찰치를 별도 필드로 두는 대안도 있으나, 사용자 요청의 이름을 유지해 고객 preferences만 통계 객체로 바꾼다. 추천 대화의 RecommendationState.preferences는 기존 문자열 목록을 유지한다.

## 데이터

- `points`, `stamps`: 현재 잔액, nullable StrictInt(ge=0). 고객 자료에 명시된 값만 사용한다. 누락/null과 명시적 0을 구분한다. 주문별 stamps_earned 합계를 현재 잔액으로 사용하지 않는다.
- `PurchaseStatistics`: order_count, total_spent, menu_quantities, category_quantities, temperature_quantities. 주문 원본의 고객 ID로 한정하고 고유 주문 ID 단위로 합산한다. 결제액은 이미 할인·옵션을 포함한 total_price를 더한다. 온도 없는 항목은 온도 통계에서 제외한다.
- CustomerProfile.preferences: PurchaseStatistics 또는 null. 조회한 고객은 주문이 없으면 빈 통계, 아직 조회하지 않았으면 null이다. 현재 주문·메뉴로 매번 집계해 State에 저장하며 고객 JSON에 파생 통계를 중복 저장하지 않는다.
- 고객 자료의 과거 preferences 문자열 배열은 새 구매 통계로 신뢰하지 않고 현재 주문에서 재계산한다. 임의로 세션 필터로 복사하지 않는다.
- 취소·환불 상태가 없으므로 저장된 주문 기준 통계임을 표시한다. 고객 ID 없는 주문을 특정 고객 통계에 넣지 않는다.

## 추천 연결

저장 알레르기와 고객 직접 조건을 우선한다. 통계는 후보를 제한하는 규칙으로 사용하지 않고 필터 통과 후보를 메뉴 구매 수량, 카테고리 구매 수량 순으로 안정 정렬하는 참고값으로 쓴다. 구매가 없으면 기존 메뉴 순서를 유지한다. 고객 조건 미확인 질문과 후속 수정, null/[] 의미는 보존한다.

03 노트북 자체 스키마·고객조회·모델 입력도 맞춘다. 모델에 원본 주문이나 개인정보 대신 구매 집계만 제공하며, 과거 구매로 알레르기나 확정적 취향을 추정하지 않도록 프롬프트에 명시한다. 분류·주문 서비스의 customer 제외 정책은 유지한다.

## 범위와 검증

schemas/session_state.py, common/customer_store.py, 03 노트북, 추천 도구 프롬프트와 관련 테스트만 수정한다. 고객·주문 원본, 기존 04/05, 영수증 적립 기능과 잔액 갱신은 이번에 바꾸지 않는다.

잔액 누락/0/잘못된 값, 고객별 통계·중복 주문·할인 총액·비회원 제외, 통계와 세션 조건 분리, 알레르기 우선과 후보 순위, 고객 전환, 기존 모델 개인정보 제외를 검증한다.
