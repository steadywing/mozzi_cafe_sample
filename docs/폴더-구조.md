## 파일 구조

현재 파일과 폴더를 기준으로 정리한다. `notebooks/`에는 기초 사용법과 기능별 실습을 작성한다. 작성·검증 기준은 [노트북 작성 규칙](노트북-작성-규칙.md)을 따른다. 그 밖의 새 파일은 필요한 기능을 구현할 때 추가한다.

### 파일별 책임

- **`main.py`**: 앱과 라우터, 정적 파일 및 서버 수명주기를 연결한다.
- **`routers/test_pages.py`**: `/test/...`의 HTML 화면을 명시적으로 연결한다.
- **`routers/test_samples.py`**: `/test/api/search/...`와 `/test/api/points/...`의 예시·샘플 이미지를 제공한다.
- **나머지 `routers/`**: `/chatbot/...` 처리 요청과 `/test/api/...` 자료·기록 요청을 받아 함수 결과를 돌려준다.
- **`schemas/`**: 요청, 상태 및 내부 데이터의 형식을 정의한다.
- **`services/`**: 모델 호출과 한 턴의 처리 순서를 작성한다.
- **`common/`**: 클라이언트, 프롬프트 및 JSON 저장소처럼 여러 곳에서 사용하는 코드를 둔다.
- **`prompts/`**: 모델에 전달하는 공통 지침과 역할별 지침을 Markdown으로 보관한다.
- **`templates/`와 `static/`**: 화면 구조, 스타일, 브라우저 동작을 각각 HTML·CSS·JavaScript로 나눈다.
- **`notebooks/`**: 기초 사용법과 기능별 함수 실습을 새로 작성한다. `0_1`에는 임베딩, `0_3`에는 Jev·OpenAI 사용법, `1_0`에는 의도 분류 실습 코드가 있다. `0_1`의 FAISS 실습 저장소는 `data/embeddings/practice_0_1/`로 분리해 기존 인덱스를 보존한다.
- **`tests/`**: API, 처리 함수, 저장소, 프런트 동작을 검증하고 예제 입력을 보관한다.

모델 호출과 처리 순서는 `services/`, 데이터 형식은 `schemas/`, 저장 처리는 `common/`의 해당 파일에서 찾는다. 기존 역할에 맞는 파일을 먼저 사용하고 필요한 경우에만 나눈다.
### 현재 화면과 코드의 연결

```text
main.py
├── 서비스 구현 현황 페이지 → templates/index.html
├── 테스트 화면 → routers/test_pages.py → templates/*.html
└── 정적 파일 → static/

화면의 static/js/*.js
├── /chatbot/intent/turn → routers/intent_classifier.py → services/intent_notebook.py
├── /chatbot/order → routers/order.py → services/product_order.py
├── /chatbot/order/practice → routers/order_practice.py → services/notebook_order.py
├── /chatbot/unknown·recommendation·search·consultation·points → 기능별 routers/ → services/notebook_*.py
├── /chatbot/history → routers/history.py → common/history_store.py
└── /test/api/... → routers/testboard.py·test_samples.py·traces.py → common/ · tests/fixtures/ · data/
```

화면은 `/test/...`, 챗봇 처리는 `/chatbot/...`, 테스트 자료와 단계 기록은 `/test/api/...`에서 찾는다. 의도 분류가 기능별 API를 자동 호출하는 통합 고객용 페이지와 음성 라우터는 아직 없다. 필요한 기능을 구현할 때 파일과 연결을 추가한다.

### 데이터와 설정

- 실행에 사용하는 로컬 데이터와 기록은 `data/`, 테스트 입력 예제는 `tests/fixtures/`에 둔다.
- 메뉴 원본, 가상 쿠폰, 테스트 입력, 실행 결과는 용도를 구분해 보관한다.
- 테스트보드의 재실행으로 같은 쿠폰이 중복 갱신되지 않게 한다.
- 대화·추천 상태는 고객 또는 세션별로 구분한다.
- `.env`에는 실제 키를, `.env.example`에는 설정에 필요한 변수 이름과 예시를 적는다.
- `.env`, `.venv/`, `data/`, 업로드한 고객 이미지·음성은 버전 관리에 넣지 않는다. 현재 `.gitignore`를 따른다.
