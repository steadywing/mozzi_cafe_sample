# 가상 데이터

모찌카페 챗봇이 사용하는 가상 데이터다. 실제 매장·고객 정보가 아니다.

## 파일

| 파일 | 내용 | 사용하는 플로우 |
|---|---|---|
| `menu.json` | 메뉴 17개: 가격·재료·알레르기·맛·별칭·판매 여부·이미지 경로 | 상품검색·추천·카페정보문의·주문 |
| `menu_images/` | 메뉴 대표 이미지 (`{menu_id}.png`) | 상품검색 |
| `search_images/` | 상품검색 테스트용 고객 사진과 설명 | 이미지 임베딩·상품검색 테스트 |
| `cafe_docs/` | 카페 안내 문서 7개. 파일명이 카페정보문의 답변의 출처가 된다 | 카페정보문의 |
| `order_options.json` | 음료 옵션 안내 기준 가격과 적용 가능한 메뉴 ID | 상품 주문 검증·모의 금액 계산 |
| `events.json` | 상시 스탬프 규칙·발급 쿠폰 목록·혜택 사용 기록 | 스탬프 적립 |
| `customers.json` | 회원 10명: 이름·마스킹 전화번호·생년·성별·가입일·등급·마케팅 동의·최근 방문일·현재 포인트 | 음성(생년 → 나이대)·포인트 적립 |
| `orders.json` | 2026년 9~10월 구매 내역 40건: 메뉴·온도·수량·옵션·금액·스탬프 | 현재 플로우에서 사용하지 않음 (추천 참고용 후보) |

상품검색 테스트 사진은 `search_images/`에, 쿠폰 이미지와 세션 상태 예시는 `tests/fixtures/`에 둔다.

기존 자료와의 연결을 유지하려고 `events.json`, `events`, `event_id`, `participations`와 문서 파일명은 유지한다. `participations`는 쿠폰 혜택 사용 기록이며, 상시 운영이므로 `start_date`와 `end_date`는 `null`이다. 기존 `stamp_2026_autumn` 값은 연결용 ID로만 사용한다.

## 값 규칙

- `allergies`·`ingredients`·`preferences`: 미확인은 `null`, 없음은 `[]`
- 알레르기 이름은 식약처 표시 대상 이름으로 통일한다: 우유, 대두, 밀, 난류, 땅콩, 호두, 복숭아 등
- `temperatures`: 디저트처럼 온도 선택이 없으면 `[]`
- `sweetness`: "없음"·"낮음"·"보통"·"높음", 미확인은 `null`

## 일부러 넣은 테스트 포인트

- **재료 미확인 메뉴**: `dessert_weekly_mochi` — 재료·알레르기가 `null`
- **판매 중지 메뉴**: `dessert_chestnut_mochi` — `available: false`
- **닮은 메뉴**: 카페라떼·플랫화이트, 인절미·흑임자 (라떼와 모찌 모두)
- **혜택을 이미 사용한 쿠폰**: `MOCHI-2026-0003` — 이미 `participations`에 기록됨
- **여분 쿠폰**: `MOCHI-2026-0006` — 이미지 없이 직접 입력 테스트용
- **스탬프와 혜택 사용 기록 일치**: cust_002는 10/6~10/20 주문으로 스탬프 10개를 모은 뒤 쿠폰 `MOCHI-2026-0003`으로 무료 혜택을 사용했다
- **다양한 구매 패턴**: 아메리카노 단골(cust_002), 디저트 포장 위주(cust_004), 항상 오트 음료로 바꾸는 고객(cust_006), 디카페인 고객(cust_007), 첫 방문(cust_010), 비회원 주문(`customer_id: null`)
- **판매 중지 메뉴의 과거 주문**: 9월 주문에 `dessert_chestnut_mochi`가 있다

## 포인트 데이터

- `customers.json`의 `points`는 실습을 위해 임의로 정한 현재 보유 포인트다. `0`은 잔액이 없는 상태다.
- 적립률과 적립 이력은 아직 정하지 않았으며, 이 잔액을 주문 금액에서 계산한 것으로 보지 않는다. 영수증 중복 적립 확인에는 별도의 처리 기록이 필요하다.
- 기존 스탬프 자료는 과거 기능 자료로 보존하며, 새 포인트 잔액과 합치지 않는다.

## 고객 정보와 대화 조건의 구분

- 회원 DB(`customers.json`)에는 알레르기·선호·음성 선호를 저장하지 않는다.
- 알레르기·선호는 추천 대화 중에 묻고 세션 상태에만 저장한다. 예시는 `tests/fixtures/session_states.json`에 있다.
- 구매 내역의 옵션(예: 오트 음료 변경)으로 알레르기를 추정하지 않는다. 알레르기는 고객이 직접 말한 값만 사용한다.
- TTS 기본 음성은 `birth_year`로 계산한 나이대를 사용한다.

## 문서에 일부러 넣지 않은 주제

상담에서 "확인할 수 없다"고 답하는지 확인하는 질문이다.

- 배달 주문, 단체 예약, 홀케이크 주문
- 메뉴 칼로리·영양 성분
- 포인트 적립률·멤버십 혜택

## 데이터 수정 주의

- 스탬프 적립·혜택 사용을 다시 실행할 때는 `events.json` 원본을 직접 바꾸지 않고 테스트용 사본을 사용한다.
- 주문 금액은 `menu.json` 기본가와 `cafe_docs/04_음료_옵션.md` 옵션 금액으로 계산했다. 메뉴 가격을 바꾸면 주문 내역도 함께 맞춘다.

이미지 검색 실습의 `embeddings/menu_images.faiss`와 `embeddings/menu_images.json`은 `04_이미지임베딩.ipynb`에서 생성합니다. FAISS 인덱스에는 정규화한 이미지 벡터를, JSON에는 모델 ID와 메뉴 ID 순서를 저장합니다. 두 파일을 함께 보관합니다. 사진이나 모델을 바꾸면 노트북에서 색인을 다시 생성하세요.
